# Scene Engine

**Version:** 1.0

**Status:** Draft

**Owner:** Scene & Exploration System

---

# 1. Purpose

The Scene Engine is responsible for translating the current World State into an explorable scene.

It answers the question:

> **"What does the player currently experience?"**

Unlike a traditional game engine that renders a 3D environment, the Scene Engine constructs a rich, structured representation of the user's immediate surroundings.

Every scene shown in the UI is generated by this engine.

---

# 2. Responsibilities

The Scene Engine is responsible for:

* Constructing the current scene
* Generating environmental narration
* Determining visible characters
* Determining visible objects
* Listing available actions
* Building navigation options
* Requesting media generation
* Refreshing scenes after world changes

It is **not responsible** for:

* Dialogue generation
* World simulation
* Relationship updates
* Timeline mutations
* Character reasoning

The engine produces a Scene object.

Example

```json
{
    "location":"Great Hall",

    "title":"Great Hall",

    "description":"Morning sunlight pours through the enchanted ceiling.",

    "visible_characters":[...],

    "visible_objects":[...],

    "available_actions":[...],

    "available_exits":[...],

    "ambient_audio":"great_hall_morning.mp3",

    "image":"scene_001.png"
}
```

The frontend renders this object directly.

```text
Location
```

# 9. Visibility Resolution

Not everything in a location is visible.

Determine

✔ nearby characters

✔ nearby objects

✔ hidden objects

✔ hidden characters

✔ blocked exits

Example

```text
Library

Characters

Hermione

Visible

↓

Snape

Hidden behind shelf
```

---

# 10. Environmental Description

Scene descriptions should be dynamic.

Instead of

```text
The Great Hall has four tables.
```

Generate

```text
Morning sunlight spills across the enchanted ceiling.

Students quietly enjoy breakfast while owls glide overhead carrying the morning post.
```

The description should reflect

* time
* weather
* active events
* occupants

---

# 11. Character Presence

Every visible character includes

```json
{
    "id":"char_harry",

    "name":"Harry Potter",

    "state":"Talking",

    "emotion":"Happy"
}
```

Characters are summaries.

Dialogue is generated later.

---

# 12. Object Presence

Objects include

```json
{
    "id":"obj_sorting_hat",

    "name":"Sorting Hat",

    "state":"Idle"
}
```

Objects expose interactions.

---

# 13. Active Events

Scene includes active events.

Example

```text
Breakfast

↓

Quidditch Practice

↓

Sorting Ceremony
```

Events influence narration.

# 14. Available Actions

Actions depend on scene.

Example

```text
Talk

Travel
```

# 15. Navigation

Scene contains valid exits.

Example

```text
Great Hall

↓

Library

↓

Entrance Hall

↓

Courtyard

↓

Kitchens
```

Only reachable exits appear.

---

# 16. Scene Refresh

Whenever World State changes

```text
Simulation

↓

Scene Refresh

↓

Return Updated Scene
```

The frontend never manually edits scenes.

---

# 17. Narration Rules

Narration should

✔ describe

✔ immerse

✔ remain concise

✔ avoid spoilers

✔ avoid repetition

Narration should not explain game mechanics.

---

# 18. Media Requests

If media generation is enabled

Scene Engine builds

```json
{
    "location":"Great Hall",

    "time":"Morning",

    "weather":"Sunny",

    "characters":[
        "Harry",
        "Hermione"
    ],

    "activity":"Breakfast"
```

---

# 19. Scene Caching

Scenes should be cached.

If

```text
Location unchanged

Time unchanged

World unchanged
```

Reuse previous scene.

Avoid unnecessary LLM calls.

---

# 20. Validation

Validator checks

✔ location exists

✔ characters valid

✔ objects valid

✔ exits valid

✔ actions valid

✔ events valid

Reject incomplete scenes.

# 23. Frontend Contract

The frontend never queries the Universe directly.

It only renders the Scene object.

Typical flow

```text
Scene

↓

Location Header

↓

Illustration

↓

Narration

↓

Characters

↓

Objects

↓

Available Actions

↓

Exits
```

This keeps the frontend stateless.

---

# 24. Performance Considerations

The Scene Engine should:

* reuse cached location descriptions
* avoid regenerating narration unless context changes
* only process nearby entities
* request media asynchronously

The goal is to keep scene loading fast while maintaining immersion.

# 27. Summary

The Scene Engine is the **eyes** of Headcanon.

It transforms the raw World State into an immersive, explorable experience by constructing a structured representation of the player's surroundings. Every location, character, object, event, and available action is grounded in the current simulation, ensuring that users experience a living world rather than a static sequence of chat messages. The Scene Engine is what makes Headcanon feel like stepping into a story instead of talking about one.
