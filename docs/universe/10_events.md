# Events

## Purpose

The Event System manages all occurrences within the universe.

Events represent actions, story milestones, environmental changes, character decisions, and user-driven interactions that modify the World State.

They are the primary mechanism by which the simulation advances.

---

# Responsibilities

The Event System is responsible for

- Recording story events
- Scheduling future events
- Triggering simulations
- Updating the timeline
- Creating character memories
- Maintaining event history

---

# Event Lifecycle

Every event progresses through the following states

Pending

↓

Triggered

↓

Active

↓

Completed

or

Pending

↓

Cancelled

or

Pending

↓

Modified

---

# Event Categories

## Canon Events

Events extracted directly from the original story.

Examples

- Harry receives Hogwarts letter
- Battle of Hogwarts
- Quidditch World Cup

Canon events may be delayed or modified depending on user actions.

---

## Simulation Events

Generated by the simulation.

Examples

- Hermione studies in library
- Draco starts an argument
- Merchant arrives at town

These events increase world realism.

---

## User Events

Created directly by player actions.

Examples

- User talks to Harry
- User gives Ron a sword
- User travels to Hogsmeade

---

## World Events

Large-scale events affecting multiple entities.

Examples

- Rain begins
- Castle lockdown
- Festival starts
- Earthquake

---

## Character Events

Personal events affecting one or more characters.

Examples

- Character sleeps
- Character eats
- Character discovers clue
- Character changes goal

---

# Event Structure

Every event contains

- Event ID
- Event Type
- Title
- Description
- Timestamp
- Participants
- Location
- Trigger
- Prerequisites
- Consequences
- Current Status

---

# Triggers

Events may be triggered by

- Time
- User actions
- Character actions
- Relationships
- World conditions
- Previous events

Example

If

Relationship(User, Hermione) > 80

↓

Secret Conversation Event

---

# Consequences

Every completed event may modify

- Character memories
- Relationships
- Timeline
- Objects
- Locations
- Emotional states
- Future events

No event should exist without clearly defined consequences.

---

# Event Queue

The Event Queue stores future events waiting for execution.

The Simulation Engine continuously evaluates whether queued events should activate.

Priority

Critical

↓

Major

↓

Normal

↓

Minor

---

# Event History

Completed events are stored permanently.

Each record contains

- Original event
- Final outcome
- Timestamp
- Generated consequences

History is never deleted.

---

# Event Validation

Before execution

Verify

- Prerequisites satisfied
- Participants exist
- Location exists
- Timeline consistency
- World rules remain valid

Invalid events are cancelled.

---

# Event Persistence

Every event update is persisted after

- Creation
- Modification
- Completion
- Cancellation

Snapshots preserve the complete event history.
